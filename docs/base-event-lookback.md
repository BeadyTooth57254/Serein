# 自动摘要的旧 Event 回看范围

设置 → 配置 → 自动摘要配置中的 **旧 Event 回看天数（创建时间）** 默认是 3，可保存 1–365 之间的整数。对应设置字段为 `pipeline.base_event_lookback_days`，通过已有认证设置接口 `PATCH /v1/settings` 修改，例如：

```json
{"pipeline":{"base_event_lookback_days":3}}
```

旧实例没有保存该字段时使用默认 3 天；保存其他设置不会清除已经设置的天数。API 拒绝布尔值、小数、数字字符串以及范围外的整数。

## 时间口径

首次构建本批候选材料时，以服务端当时的 UTC 时间为基准，取前 N × 24 小时至基准时间的闭区间。默认 3 天即 72 小时，不按日历零点切分。时间范围随候选快照保存，重试不随时钟滚动。

只比较当前 Event 记录的 `fact_events.created_at`。不使用 `updated_at`、最后注入时间、绑定原话的开始或结束时间，也不判断话题最近是否活跃。聊天发生时间与 Event 记录创建时间是两个不同的字段：原话很旧、但 Event 记录最近创建，仍可能入选。

现有同轨道和有效版本限制保留：`status='active'` 表示记录尚未被归档、替换或删除，不是“最近活跃”。范围外的 Event 不加载它的绑定原文；入选后仍完整读取绑定原文，不截断消息、不改变来源归属。

## 生效范围

天数使用新批次保存的输入配置。修改天数对新批次生效；已经冻结的候选材料、Curator 请求与已完成步骤保持原样，不自动重建。因此修改此项不会立即缩小一个已经冻结并超限的旧任务。

这项设置只控制自动整理时的旧 Event 候选，不修改记忆正文、创建时间、归档状态、召回规则或原文存储；也不限制本轮待处理的新原话。没有入选的旧 Event 仍按原有规则参与召回。

## 当前边界

本次是创建时间筛选，不是总字符预算，也不是整个续写链的年龄限制。若续写或合并产生新的后继 Event 记录，候选筛选仍按该记录自己的 `created_at`，不追溯祖先最早的创建时间。单个入选 Event 的原文很大、近期集中创建很多记录，仍可能超过完整提示词字符上限。

候选分轮读取、总字符预算、祖先年龄限制，以及既有冻结任务的显式重建不在本次改动范围。

## 测试

`tests/test_pipeline_base_window.py` 使用合成内存 SQLite 数据，覆盖默认值、配置校验、时区和微秒边界、忽略最近更新时间、保留生命周期限制、范围外原文不读取，以及候选窗口冻结。完整检出并安装测试依赖后运行：

```sh
python -m pytest -q tests/test_pipeline_base_window.py
```
